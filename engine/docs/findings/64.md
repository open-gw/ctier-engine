## What Apigee is expected to fail or skip

From permitted divergence (61) and the
stock package:

- **Skips (capability):** C10×2, C16,
  and pending/approve rows, until the
  operator builds a collector /
  observer / live approval URL. Reason:
  `requires a capability this target
  lacks`. About Apigee+package, not
  their org.
- **Skip (generation):** C13 always on
  a URL run.
- **Skip (level):** level-3-only rows
  when `kit_level: "2"` (the example
  default).
- **Inconclusive:** C12 on bare `404`
  without a routed-but-ungoverned
  `/estate/unknown`.
- **Fail if mis-aimed:** `kit_level: "3"`
  with placeholder custody → withhold
  rows fail; missing token scopes →
  401/403 fails.
- **Cannot claim from this artefact:**
  C11 vs PreProxy FlowHook; durable
  decision sink; local runtime parity.

Kong/APISIX matrices after 63 are
clean with reasoned skips. Apigee's
first honest column will be mostly
skips until someone wires records and
an observer. That is the point.

## Does the kit assume a rig we control?

The **checklist** (`conformance-kit/1.0`)
takes a URL and a token. It does not
start Docker. It does not merge Kong
fragments.

**Provisioning** still assumes an
operator can deploy the generated
proxy and mint a token. Live matrices
in this repo used compose stacks the
project controls; C12 on Kong was
inconclusive until a route was added
(62). Apigee handoff makes that
operator step explicit. The kit does
not add the route.

## Dry-run

**Self-blind dry-run**, not a third
party. Fresh shell. Followed only
`COVER.md` → `PROVISION.md` →
`RUN.md` against this tree. Kong /
APISIX as stand-in for Apigee; Docker
had no live stack up.

### Where the reader stopped

**First stop: `PROVISION.md` §3 —
"Zip `generated/apiproxy` and import
it into your organisation."**

There is no Apigee organisation in
this environment. The handoff docs do
not name a local stand-in URL or port.
A reader who knows Apigee and not this
repo cannot invent Kong's published
port from the package alone.

Earlier steps that worked without
prior knowledge:

- `COVER.md` readable; terms either
  defined or avoided.
- Engine already importable via existing
  `.venv` (a stranger without that
  would hit `pip install` next — the
  path is stated).
- `generated/` already present.

### After noting the stall (stand-in probe)

Substituted `gateway_url:
http://127.0.0.1:18100` out of band
(not from the docs) and a non-placeholder
token. `./run.sh` then raised
`ConnectionRefusedError` — no result
file, a Python traceback. **Second
friction:** a down URL is not turned
into a result file or a one-line
error. Recorded; not fixed in this
pass (would be runner UX, and the
five commits stayed documentation /
packaging as named).

Nobody external was available. This
self-blind run counts; it is not a
third-party reader.

## Observation

The matrices after 63 say both live
engines are clean. The Apigee package
before this pass told a practitioner
to assemble harness flags and read
VERIFY claims. The first blind walk
stopped at deploy — before any case
ran. That stop is not a red C-row. It
is the usual cost of a framework whose
proofs lived on a rig its authors
started. The handoff now says so up
front, names every config value, and
refuses to pretend Trace is a records
URL. The next stranger still has to
have an Apigee org. We cannot document
our way around that. We can stop
asking them to know what "inconclusive"
meant without a sentence, and we can
stop asking them to diagnose.
