# 14a.1 — make the rig prove the chokepoint

## Answers

**Part 4.** Did any existing live test pass because it reached the
backend directly? **No.** Corpus, assumptions, withhold, and the
rest go through the proxy (`echo_json` / `request`). No previously
green result was measuring agent→backend.

**Instead of direct access.** Two harness paths used the published
echo port. Neither was a claimed measurement of agent→backend.

- Stack start waited on `http://127.0.0.1:18080/` (Kong) and
  `19080` (APISIX). Replaced by compose `depends_on: echo` healthy.
  The host wait is gone.
- `test_tier3_approve_executes_from_persisted_context` read
  `GET /_harness/requests` from the host. Execute was already
  custody → echo; the log was a second look. Same endpoint now via
  `docker compose exec` into echo.

**None reopened the network.** No test publishes the echo port or
puts echo back on `edge`.

**Gate.** `pytest -q`: **276 passed, 43 skipped**. `pytest --live
-q`: **314 passed, 5 skipped** (236.88s).

14a found the mock backend on the default compose network, published
to the host. The live suite had measured what the enforcement point
does when a request goes through it. It had never measured that a
request has to.

## Topology

Echo sits only on the `upstream` network (`internal: true`). Kong,
APISIX, and custody attach to `upstream` and to `edge`. Gateway
ports stay published. Echo's host ports (`18080`, `19080`) are gone.

`outsider` is on `edge` only. That is where an agent sits.

## What it proves

The tests assert two different failures from outside the gateway:
the unpublished port from the host, and no route from `outsider`
(by name and by echo's address). They prove this compose file. They
do not prove a deployment's topology. `docs/portability.md` now
says what the adopter still owes.

## A property nobody had asked a test to fail

The identity headers had no consumer but the test asserting they
existed. The chokepoint had no assertion at all. Both were found by
an audit rather than by a failure. A test that asserts a property
nobody questions is doing different work from one that asserts a
feature somebody uses. This project has been short of the first
kind.

## NEW-MATTER

None. Isolation is topology in the rig, and the two deployment
conditions are obligations, not a new engine mechanism.
