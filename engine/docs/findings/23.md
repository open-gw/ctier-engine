# 23 — stop emitting a wrong idempotency key on Apigee

Date: 16 September 2026. Requires 22. Did not edit the spec.

## Removal

Apigee's generated `set-upstream-provenance.js` HMACed
`[anchor, path, '{}', '', agent, task]`. Query and body were
literals. Every distinct body of an operation collapsed onto one
`Idempotency-Key`. A backend that honours the header would return
the first response for the second request and never execute it.

The derivation is gone. The JS still mints `x-ctier-correlation-id`.
It does not set `Idempotency-Key`. Fixing the JS would have meant
solving 22's canonicalisation problem in a third language, on a
target with no live differential.

## Alignment

Apigee was the only target emitting a derived key on the forwarded
path. Kong and APISIX never have: they copy `idempotencyKey` from
the ledger when custody is compiled, and otherwise set nothing.
After this change all three behave the same way. The derived key
exists where it can be computed correctly — custody's execute path.

No target provides the derived key on the forwarded path, for the
reason 22 established, and Apigee no longer provides a wrong one.
That is not the removal of a protection.

## Guard

`test_no_target_emits_a_derived_idempotency_key_on_the_forwarded_path`
is parameterised across apigee, kong, and apisix, with and without
custody. Generated artefacts must not contain `crypto.hmac` or
`ngx.hmac`. Apigee's provenance JS must not mention
`Idempotency-Key`. Kong and APISIX may still copy a stored ledger
key.

## Part 4 — other generated JavaScript

The Apigee target emits two JS resources:

| Resource | What it does |
|---|---|
| `strip-ctier-namespace.js` | Prefix-walks request header names and removes `x-ctier-*`. No hash, no digest, no comparison of a derived value. |
| `set-upstream-provenance.js` | Mints a correlation id. After this task, nothing else. |

There is no third script. AssignMessage policies write compiled
integers (`ctier.tier`, the deployment digest). The digest is
SHA-256 of the qualified spec at generate time, in Python, not a
per-request truncation of C7's material.

**Nothing else.** The truncated HMAC was a one-off, not a habit
that survived in another policy.

## Goldens

Four generate cases. Each moved only
`apiproxy/resources/jsc/set-upstream-provenance.js`. No other file
in those bundles changed. Nothing else was coupled to the HMAC
policy.

## The line worth recording

This code was written, reviewed, committed and shipped as
golden-correct. It was found only because a task asked two
implementations to agree on a value, and the third one disagreed
with both. Golden-file verification proves an output has not
changed; it cannot notice that the output was wrong when the
golden was taken.

## NEW-MATTER

None beyond 22's already-filed question (scope 1.5.0's MUST to
custody). This task makes Level 2 uniform in the engine; it does
not decide the specification.
