## Part 1 — why APISIX was silent

Kong records a compiled Tier 4
refusal. APISIX returned `423` /
`halt_and_hand_off` and wrote no
decision. Same composition.

**Cause: the third option.** Recording
was attached to paths, not to the
decision.

- `execute` → `_lua_forward_provenance`
  → `ctier_emit_sink("[ctier-decision]")`
- `withhold` → Attempt on custody-down
- `abort` (compiled T4, L2 Tier 3,
  excluded) → stock `fault-injection`
  only. Status and body. No Lua. Emit
  helper unreachable.

Not a short-circuit before a later
recording phase. The abort path never
called the sink.

### Other dispositions that shared the gap

| Disposition | Before | After |
|---|---|---|
| Compiled Tier 4 | silent | Decision, sink + seq |
| L2 Tier 3 / excluded | silent | Decision `refuse-provisioning` |
| Floor-escalated T4 | exit before log | Decision, then exit |
| Bounds abort | exit without emit | Decision, then exit |
| Catchall C2 (composed undeclared) | silent 423 | **still silent** |
| Catchall unassigned | Attempt | unchanged |
| Custody-down 503 | Attempt (35) | unchanged |
| Execute | Decision | unchanged |

Catchall C2 remains a gap. Not the
c10 row. Reported, not fixed here.

## Part 2 — the fix

Compiled abort is serverless: allocate
epoch/seq, `ctier_emit_sink`, then
exit. Same sink and sequencing as
execute (50). No ledger POST — stock
T4 still does not revoke.

symptom (refuse, no record), different
cause. Fixed the abort cause, not a
second instance of 35.
