## Sink contract

A sink accepts a `decision-record/0.2.0` object. An implementation must emit every required field so a collector can validate the payload as that schema, not as a diagnostic that happens to share names.

Two implementations:

- **Custody** — runtime service. Durable because the ledger is append-only storage. Needs a hop.
- **Gateway-log** — no runtime service. The enforcement point emits one JSON object prefixed `[ctier-decision]` on the gateway's existing structured log. Durability is the operator's collector. An implementation whose records can be lost has not recorded them; this sink does not pretend otherwise.

Stdout as a product surface is not offered. Gateway logs are the operator's pipeline, declared `durable: operator`.

## Structured logging on the three targets

Kong and APISIX: `kong.log.notice` and `ngx.log(ngx.NOTICE, …)` write to the gateway error log. Live tests parse `[ctier-decision]` from that file and `validate_record`. No new `io.open` on the request path. `io.open` remains only on Kong's Attempt fallback.

**Apigee `print()` is not a sink.** Apigee's JavaScript object model documents `print()` as debug output for the Trace/Debug tool (`stepExecution-stdout`). It is not written to Cloud Logging. Google's own answer (August 2022): the JavaScript callout does not log print statements to GCP Logging; they are available in the Debug console only. Production logging is a MessageLogging policy, typically in PostClientFlow. This task did not add that policy — it would be a new component, and the instruction was to name a target that cannot before reaching for anything that blocks.

So: Kong and APISIX emit records at Levels 1 and 2. Apigee generates a schema-shaped object in JS that an evaluator can read *while a trace is running*. That is the same standing as everything else Apigee: artefact-only. Claiming all three targets emit records would be overstated.

## Level 1

`generate(..., observe=True)` compiles classified operations to execute, including Tier 4, and still emits the decision record (on Kong and APISIX). Scope and RaiseFault / fault-injection are not applied. JWT remains because it is how the live gateways accept a caller, not a consequence decision.

## Deployment requirement (draft for the spec — 16d exclusion form)

ctier does not guarantee durability of gateway-log decision records; an operator who has not configured a durable collector for `[ctier-decision]` lines has not recorded them.

Filed in spec 1.10.0 as requirement 4.
