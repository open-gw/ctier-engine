# 13a — exclusion and suspension at the authorisation layer

Tier 4 returned `423 AgentSuspended` and C8 rejected a withhold; nothing
was paused. This task makes both of those acts remove the operation's
scope from the agent client. The next token that does not carry it is
401. The request that still holds a previously issued token is not.

## One mechanism

Exclusion is a scope never granted. Suspension is the same absence,
produced later. The generator emits `authorization.yaml` and a Keycloak
realm in which classified operations become client scopes named
`operation-{operationId}`, granted to `agent-a` unless `x-ctier-exclude`
is set. Custody `decide(reject)` and a ledger Decision with
`refuse-and-suspend` call `directory.revoke`. Expiry of a pending
withhold does not. Offline: `NullDirectory` records the reject and stays
empty across `review_queue` materializing `expired`.

They reduced to one mechanism in the grant, not only in prose. The
triggers differ (compose time vs C8 / T4). The compiled fact is the same
row in the client's default client scopes.

## What the request path does not do

Kong OSS has no bundled plugin that requires a scope. Enterprise
`openid-connect` / `jwt-signer` `scopes_required` is not available.
The generated deck therefore attaches the bundled `jwt` plugin
(RS256, `claims_to_verify: [exp]`, `key_claim_name: cid`) and a
`required_scope` on the existing `ctier` instance. Lua reads `scope` on
the bearer Kong already accepted. `handler.lua` contains neither an
introspect URL nor a userinfo call. A GET to custody asking whether the
agent is paused is still absent.

Excluded operations keep `jwt` and omit `required_scope`. A token that
reaches them is 403 provisioning — detection that prevention failed —
rather than 401, which would disagree with the reference adapter.

`refuse-unauthorized` is an observation (HTTP 401), not a classified
disposition. It is not in corpus 0.3.0's enum, so the handwritten
suspension sequences are not merged into the 24-case differential. No
Decision is written for a 401.

## Token lifetime, measured

Live, a client-credentials token from the imported realm has
`exp - iat` equal to the Configured 30 s lifetime. That number is in
[`measurements.md`](../measurements.md). The already-issued token still
classifies as Tier 4 after revocation (423, not 401); the next token is
401. The delay is the remainder of that lifetime on tokens already
issued. An hour-long token would be an hour-long window. Closing it by
calling the authorisation server on the request path is the thing
ADR-003 forbade.

Pending expiry (the custody deadline) is a different clock. The live
expiry case waits out the **token**, not the 86400s review period the
rig leaves at the production default. Offline already shows
`review_queue` does not revoke. After that wait, a new token still
executes a classified Tier 1.

## What Keycloak's realm model would not express

- **Lookup claim `cid=ctier`.** Kong JWT credentials match `iss` or a
  configured key claim. Keycloak's `iss` follows the hostname the token
  was requested with (`127.0.0.1:18400` vs `keycloak:8080`). A hardcoded
  protocol mapper on client scope `ctier-identity` puts `cid: ctier` on
  access tokens so the consumer secret's `key` is stable. That mapper is
  a realm-model accommodation, not a governance concept.
- **Admin API via `admin-cli` password grant against `master`.** Importing
  a service-account client with `realm-management` roles into the realm
  JSON was avoided. Bootstrap admin `admin`/`admin` is a rig secret.
- **Scope names `operation-foo`, not `operation:foo`.** Keycloak client
  scope names reject the colon. The portable document uses the same
  hyphenated form so generate stays one mapping.
- **`secret: unused-rs256` on an RS256 jwt_secret.** decK's file schema
  requires `secret` even when `rsa_public_key` is the material Kong
  verifies with.

The RSA keypair is fixed in-tree (`authz/public.pem`,
`authz/keycloak-rsa.json`) so `generate()` stays byte-identical. Keycloak
`26.3.3` publishes `linux/arm64`; the image is pulled at `compose up`
the same way Kong is. Tests do not call the network themselves.

## Live posture

`pytest -q` (socket-blocked) is green. `pytest --live` is green: 258
passed, including Keycloak import, token issuance, T4 then 401 after
refresh, C8 reject then 401, and an expired withhold that still
executes Tier 1. Live remains opt-in.

The session-scoped rig imports the generated realm, issues
client-credentials tokens as `agent-a`, and `ensure_granted` restores
scopes after a spec other than REFERENCE is loaded. Suspension tests
must use `X-Agent-Id=agent-a`: revoke looks up the Keycloak client by
that id and no-ops if it is missing. Other live tests keep
`agent-live-*` so a T4 in the ledger suite does not strip `agent-a`.
Client credentials required `serviceAccountsEnabled: true` on the agent
client; with it false the realm imported and nothing could obtain a
token.

Delegation-chain integrity is 13b. It was not held for this task.

## NEW-MATTER

File one item, not three. Exclusion and suspension as a **single compiled
absence, with bounded-staleness enforcement:** the scope is absent from
the credential rather than checked against a service, so the same
mechanism serves a design-time decision and a runtime one — and the
enforcement point is forbidden from contacting the issuer per request
to close the resulting delay, accepting a bound equal to the remaining
token lifetime instead. That constraint is the mechanism, not a
limitation of it.

The 30-second figure is not this item. It is a measurement
([`measurements.md`](../measurements.md)). The `cid` mapper is a
Kong-OSS binding, not this either.
