# 14c — make the reference implementation conform to 1.5.0

1.5.0 was a specification its only implementation failed, in four
places, none of which any test checked. This task closes that gap
on all three targets and writes down the corpus question it still
does not answer.

## Kong's prefix and `X-Correlation-Id`

**The prefix strip had in fact left `X-Correlation-Id` open.** Nothing
else covered it. `strip_inbound` compared `string.sub(lower, 1, 8)`
to `x-ctier-`. `X-Correlation-Id` does not start with that. There was
no second list. Live `test_kong_prefix_left_x_correlation_id_open`
sends the alias and checks the echo: the agent's value is gone. The
alias is now in `ALIAS` next to the idempotency names, which were
the same class of miss.

`X-Ctier-Tier` was already a prefix hit. Assuming the prefix target
was finished because it was finished for the namespace would have
left the join-key alias on the wire.

## Correlation-id equality

Forwarded executes set `x-ctier-correlation-id` from the value the
ledger returns on `POST /v1/ledger` (Kong and APISIX when custody is
configured), falling back to the id the enforcement point minted
only if that hop does not answer.

Live tests read the echo header, `GET /v1/ledger?type=decision`, and
assert `record["correlationId"] == cid`. They matched. A non-empty
check would have passed a per-request random that was never written
to the record; this one would not.

Apigee has no local runtime. The artefact mints `messageid` on the
TargetEndpoint PreFlow (after `AM-Tier`) and does not POST the
ledger, so equality is not measured there.

## Derived `Idempotency-Key` and existing tests

Inbound `Idempotency-Key` and `X-Idempotency-Key` are stripped on
every target. Custody already derived the C7 key; `build_outbound`
emits that stored value on execute after dropping those inbound
names. On the gateway path the key is copied from the ledger 201
when custody is present.

**Level 2 does not emit a derived key.** That is a declared gap
against 1.5.0's MUST, not an oversight this task then papered over.
C7 derives from request content, stores the result with persisted
context, and forbids re-deriving at execution time. Level 2 has no
persist. HMAC-in-Lua at forward time is therefore not a dropped
experiment that failed to compile: it is request-time compute the
compiled architecture is built to avoid, attempted because the MUST
as written has nowhere else to live without custody.

The 500 was real. `ngx.hmac_sha256` plus `require("resty.string").to_hex`
on Kong, and the same idea in YAML-embedded APISIX Lua, 500'd every
Level-2 execute (seven live tests: `getBalance` and the other
execute corpus cases, Kong E1/E2, accumulation). Custom Kong plugins
already `require "resty.http"`; hashing is not banned — `ngx.md5` of
a minted string succeeded. HMAC-SHA256 and hex of a binary digest
at the enforcement point is awkward (OpenResty API, plugin vs
serverless sandbox, YAML-embedded Lua). Fixing the 500 would still
leave a key re-derived at execute, which C7 forbids.

A per-request `ngx.md5` of a minted id was tried as a stand-in so
the backend would see *a* header. That is not C7: it would look like
a key while guaranteeing a honouring backend never deduplicates. It
is gone. Level 2 strips the agent's key and emits nothing. Level 3
emits the ledger HMAC; live tests compare it to
`record["idempotencyKey"]`.

Whether the specification's MUST should be scoped to deployments
with custody, or Level 2 needs another mechanism, is not this
task. `docs/portability.md` says what Level 2 defends (the agent
cannot choose the key) and what it does not (there is no
duplicate-execution defence).

Those seven tests' assertions did not need to change once the HMAC
path was dropped. They fail closed on 500, not on a missing header.

## Downstream name

`relay_headers` emits `x-ctier-correlation-id` and, through engine
0.3.0, `X-Correlation-Id`. Same window as `x-ctier-composition`.
Not a 14a-style security removal. Live 202s carry both, equal.

## APISIX phase (the extra observation)

A prefix strip in `serverless-pre-function` `phase=access` runs
*after* `proxy-rewrite`. It deleted the `x-ctier-tier` the target
had just set. Strip belongs in `phase=rewrite` at priority 21000,
before rewrite. Access-phase Lua then sets the join key. A2 (cannot
remove+set the same name in `proxy-rewrite`) is a sibling of this,
not a substitute for it.

## Corpus proposal (not implemented)

A case that asserted what reaches a backend would name the headers
the agent sends and the headers the adapter must observe on the
echo: namespace absent, aliases absent, `x-ctier-correlation-id`
equal to the decision record, derived `Idempotency-Key` present on
execute. The corpus today has `expect.disposition` and
`expect.appliedTier`; adapters already put echo headers in evidence
and then ignore them except for tier. What it lacks is an
`expect.upstreamHeaders` (or a deny-list plus a join-key equality
flag) that the runner agrees on, not a new dimension of classification.
Cost is that field, one fixture shape, and adapter work to read the
ledger for the join. It would have stopped 1.5.0 shipping with four
untested MUSTs, and stopped Kong being correct by construction for
the namespace while forwarding `X-Correlation-Id`.

## Spec first, then the engine

This is the third time a specification artefact has been corrected
by the act of building against it, and the first time the correction
happened before anything was built rather than after. The difference
was not that review became smarter. 14b's first sentence (emit ⊆
strip) was still wrong. The difference was that the wrongness lived
in a document whose only job is to be disagreed with, so the
correction was a sentence, not three generated targets and a plugin
that had already taught the tests the mistake. Thirty tasks of
implement-then-specify paid that bill after the artefacts existed.
Writing the spec first does not remove the need to build; it makes
the first build a check of the invariant instead of a source of it.

## NEW-MATTER

Whether 1.5.0's derived-key MUST is scoped to deployments with
custody, or Level 2 needs a mechanism that is not re-derivation at
execute. Recorded as a declared gap; not decided.
