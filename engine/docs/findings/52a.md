# 52a — C16, the snapshot, and the governed set

Date: 19 September 2026. On top of 52. Independent of spec 53a.
Did not edit the spec. Documentation only. No behaviour change.

52's clause list said C1–C13. Spec 1.22.0 minted C16. The list
did not say so. The list also put `governed-set` under
requirements not met. 41 built the artefact.

## Part 1 — C16 is this repo's assertion

This tree already asserts that an unknown `x-ctier-*` header
does not reach the observer.

`engine/ctier/boundary/suite.yaml`: `namespace-unknown-audit`
sends `x-ctier-unknown-audit`; `namespace-unlisted` sends
`x-ctier-foo`. Both require the name `absent`. Live
`tests/live/test_boundary.py` runs that suite on Kong and
APISIX. `tests/test_headers_15.py` and
`tests/live/test_headers_15.py` assert the same unknown name.

The claim is those cases. It is not 53's measurement. 53 is a
different tree.

C16 is implemented. The assertion lives in the runtime suite.
Base stays **1.15.0**. This tree does not claim 1.22.0 as a
whole.

## Part 3 — what makes the list stale

The clause list is a snapshot relative to specification
1.22.0. It is stale when a new criterion is minted, a record
type this engine emits gains a version, or a clause this
table lists as not met is implemented. One line in
`docs/SPEC.md`.

## Part 2 — the governed set is built, not titled

The list said `governed-set` as a titled identifier was not
met. That under-claims.

41 built one artefact, two serialisations: `governed` on the
Kong global instance (route names) and `governed` on
`ctier-generate.json`. An operator can read the set without
parsing the deck. That is 40's discoverability obligation.

What this tree lacks is the titled identifier. It does not
publish the list under `governed-set` as 1.18.0 named it.
Has the artefact, does not publish under the title, is not
"does not implement."
