# 35 — a 503 that recorded nothing was a C10 failure

Date: 18 September 2026. Requires 34. Did not edit the spec.

## Part 0 — what each engine emitted

Asked of the path where custody is unreachable and the enforcement point
returns `503 custody_unavailable`.

### APISIX (before this task)

1. **Any record?** No. `_lua_withhold` posted `/v1/pending`, and on failure
   exited 503. No Attempt, no Decision, no log line.
2. **Where?** Nowhere. Not custody (down). Not 29's gateway-log sink. Not a
   file.
3. **Kong, same condition:** an `attempt-record/0.2.0` with `appliedTier`
   JSON-null (undetermined) and `reason=custody-unavailable`, appended to
   JSONL (`io.open` on `ledger_fallback`) so custody can ingest it when it
   returns. Until this task Kong did not also write that object to the
   gateway log.

This was a **C10 failure**, not a portability difference. C10's final
paragraph: where the policy service is unavailable and the enforcement point
refuses without classifying, the refusal MUST itself be recorded, marking the
applied tier as undetermined. A 503 with no record is the enforcement half
only. 29 had already built a sink that needs no runtime service. The gap
was routing.

## Part 1 — the fix

APISIX now `ngx.log`s `[ctier-attempt]` with a schema-valid Attempt
(`appliedTier` is `cjson.null`, not 4, not omitted). No new `io.open`, no
second hop. Kong logs the same object under the same prefix, and still
appends JSONL so ingest continues.

The records differ in transport only: Kong has a file as well as a log line.
The JSON object is the same schema. Kong's old `type=attempt` envelope field
on the JSONL line was extra relative to the schema and is gone; custody
ingest never needed it.

## Observation

The custody-unavailable path has been specified since ADR-005, restated in
C10 in 11a, and exercised by a test that asserts two `503`s. Nothing asserted
that the refusal was *recorded* — so a gap in the most safety-relevant path
survived a criterion restatement and a live test, and surfaced only because
a demo tried to show the ledger not going dark.

A test that checks the response and not the record will pass for years.

## Spec author

C10 is already in the specification. Nothing new to file except that an
implementation can satisfy the 503 and still fail the paragraph, and that
the gateway-log sink is a valid Attempt sink, not only a Decision sink.
