# 32 — Level 4 on APISIX

Date: 18 September 2026. Requires 31. Did not edit the spec.

## Property

Same as Kong: a shared dictionary populated by a background timer that
polls custody `GET /v1/floors`, and a request-time read that is a
dictionary lookup. No per-request hop. `floor_poll_ms` and `custody_timeout_ms` are
Configured (1000 ms and 200 ms); TTL is Derived (two intervals).
See [`measurements.md`](../measurements.md). An unavailable floor is
no escalation and no refusal (ADR-0011), tested with custody stopped.

## How the timer differs

Kong's `ctier` plugin is a worker module. `poller_started` is a Lua
local; `ngx.timer.at(0)` plus `ngx.timer.every` run once per worker
from `access`.

APISIX has no plugin init. Generate emits the poller inside
`serverless-post-function` on every classified route that has custody.
A pid-keyed `ngx.shared.ctier_floors:add("ctier:poller:" .. pid)`
claims one timer per worker so the copies do not each start one. The
dict itself is node config (`lua_shared_dict ctier_floors 1m` in
`targets/apisix/live/config.yaml`), not generated. An operator who
omits it gets the logged no-escalation path, not a refuse.

APISIX's plugin model made the timer awkward in exactly that way: there
is no worker-init hook analogous to Kong's handler chunk. The shm claim
is the difference, not a workaround that changes the property.

## Window

The bound is Derived: threshold-crossing plus one poll interval
(1000 ms). See [`measurements.md`](../measurements.md).

**Observed.** Escalation visible 216 ms after the crossing request.
Single sample; APISIX, 1000 ms poll interval, M3 under Docker,
18 September 2026. **The bound is one poll interval**; this sample
says the mechanism works, not how fast it is.

## Ladder afterwards

Level 4 is no longer “Kong only.” Both live gateways accumulate. The
remaining difference is how the timer starts and where the dict is
declared, plus unmeasured memory-pressure behaviour of a 1m
`lua_shared_dict`. Apigee has no live runtime for this rung. “Both
targets support Level 4” without those qualifications would overstate
it.

## NEW-MATTER

Spec 1.10.0 (task 30) still says Level 4 is target-dependent and that
the reference builds the poller on Kong and not APISIX. That sentence
is now false of the reference. The author should replace it with the
remaining difference above, not delete the qualification.

## Observation

Two implementations of the same property on two engines is exactly
where a number quietly diverges. Kong's window was classified as
Derived (the bound). APISIX's 216 ms is Observed (one sample). They
are not the same kind of number.
