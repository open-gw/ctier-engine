# 17 — APISIX as a third target

Date: 10 September 2026. Header names from 13h. Did not wait on 14 or 16.
Did not implement 14a. Did not push.

## Check 1 — custody execute path

**Direct to the backend URL.** Not through Kong or Apigee.

`HttpExecutor` (`engine/ctier/custody/execute.py`) builds
`base_url + path` and opens that socket. `base_url` is
`CTIER_BACKEND_URL` (the echo, in the live rig). `decide()` in
`service.py` calls `executor.execute(outbound)` after approval. There
is no hop that re-enters a gateway.

`x-ctier-approver` and `x-ctier-agent` therefore never meet a
gateway strip set. Specify-and-strip was never available for task 14:
a direct call never sees the strip. Removing the headers works either
way. That is the fact 14 is waiting on.

## Check 2 — the generator seam

The seam is `_all_operations` / `_classified_operations` in
`generate.py`: one list of compiled rows (path, method, tier, excluded,
bounds, handoff). Kong, Apigee, and APISIX each only express those
rows. There is no first-class `CompiledDecision` type and `mode` is
still only `"bundle"`. The files dict is the packing. Fragment mode
will consume the same rows; this target did not grow a bundle-only
wrapper around them.

Two targets had agreed because they were written by the same hand from
those functions. A third target through the same functions is the
first check that the functions, not the author, are the contract.

## A1–A4

Named tests in `tests/live/test_apisix_assumptions.py`. Image
`apache/apisix:3.13.0-debian`, arm64, standalone YAML, Admin API off.
Compose came up; the assumption run was **21.68s** the first time,
**67.61s** after custody was added to the same project.

| # | Hypothesis | Result |
|---|---|---|
| A1 | Runs declaratively on arm64, no etcd, no Admin API | **Holds.** `GET /a1/ping` echoed 200. |
| A2 | Per-route strip is declarative; plugin order is controllable | **Holds**, with a same-name constraint. `proxy-rewrite` set overwrote inbound `x-ctier-tier` and removed `x-ctier-criteria`. `_meta.priority` changed which write survived. Remove and set of the *same* name dropped the set. |
| A3 | Token scope vs operation without custom code | **Falsified.** Signed HS256 without the operation scope was 200. Missing/unsigned bearer was 401/403. |
| A4 | Shared store readable at request time, no Admin API | **Holds.** `ngx.shared.ctier_floors` was writable and readable (`x-floor-store: held`). No stock plugin uses it for a floor. |

A3 is the same shape as Kong OSS: signature is a product plugin, scope
is Lua on the accepted bearer. That is a finding about Kong's "needs
Lua" story, not a win for APISIX.

## Generate

`generate(..., target="apisix")` emits `apisix.yaml` from the same
rows, the same deployment digest, and the same `authorization.yaml` /
Keycloak realm. No new OpenAPI field.

Custom code in the generated file:

| Snippet | Why it is here | Could generate have decided it? |
|---|---|---|
| `serverless-pre-function` reads `scope` on the bearer | A3. Token-dependent. | The *name* is compiled. Whether this token carries it is not. |
| `serverless-post-function` `tonumber` of a compiled query parameter | Bounds. Request-dependent. Corpus includes `101.0` and `1.01e2`. | The escalated *consequence* is compiled. The comparison is not. |
| `serverless-post-function` POST `/v1/pending` | Level 3 withhold. Runtime. | No. Same hop Kong makes in the plugin. |

Strip, set, T3-without-custody 403, T4 423, excluded 403, and the
undeclared catch-all are stock plugins. Classification does not appear
in the Lua (`compute_tier`, criteria values, blast-radius are absent
from `apisix.yaml`).

## Differential

`ReferenceAdapter` vs `ApisixAdapter` (same observation projection as
Kong). Standard profile, stateless and sequential cases. n=24 each
level. **24/24 agree at level-2. 24/24 agree at level-3.** C11 agreed:
injected `x-ctier-tier: 1` on `PUT /config/feature-flags` was 423,
`backendReached: false`.

A third opinion that agrees with Kong and the reference is not proof
that all three are right. It is the first time two live engines have
agreed with each other. Apigee remains golden-correct and unproven.

A3 was falsified, so 13a / 13c were not required to run here. Exclusion
is in the corpus and agreed.

## Third versus second

The second target (Kong) had to invent the live suite, the observation
projection, the corpus extras, and the compiled-row functions. The
third reused them. What made it easier: the compiled decision, the
document contract (no new fields), and the corpus. What was still
work: A1–A4, the A2 same-name constraint, and minting RS256 in the
harness so APISIX did not need Keycloak for L2/L3.

If it had been harder, the reason would have been a missing seam —
classification re-implemented per target. That did not happen.

## Adversarial self-check

Would a generated file that secretly re-classified have passed? The
offline test `test_apisix_custom_lua_is_not_classification` fails if
`compute_tier` or a criteria value lands in `apisix.yaml`. The live
corpus fails if APISIX applies a different `(tier, disposition)` than
the reference. C11 fails if an inbound tier header reaches the echo.
A disagreement was to be recorded before it was "fixed". There was
none.

The weak spot is the same as Kong's: scope Lua decodes the payload
without re-verifying the signature. It runs after `jwt-auth`. That is
the accepted-bearer pattern, not introspection.
