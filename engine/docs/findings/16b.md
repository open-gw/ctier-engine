# 16b — fragment mode was deleting configuration it did not write

Task 19 found it while building a probe. Task 16 specified the
conflict report, ran, reported a conflict category it had found, and
passed its acceptance. The defect was found three tasks later by
someone building a probe, for an unrelated reason. A task can satisfy
every acceptance item it was given and still ship the thing it was
written to prevent — and the only reason this one surfaced is that a
later task needed the deleted component to still be there.

## Part 0 — why the report missed it

**Cause 1.** Check cause 3 first: `apply_or_refuse` *does* consult
the report. `wouldRefuse` raises `GenerateError` and skips the merge.
The report was not decoration for C11. That is not what happened.

The collision detector compared existing plugins to a **hand list**:
the name `ctier`, and eight Apigee policy filenames. Generate on
APISIX emits `serverless-pre-function` for the strip. That name was
not on the list, so there was no `name-collision` finding.

The estate Lua *was* noticed, as a `header-component` **warning**
(`breaks_c11: false`). Task 16's rule — C11-breaking conflicts refuse,
everything else warns — then left the merge free to drop the plugin.
That is cause 2 as the *gating* rule, not as a mis-classified collision.

So: **the detector did not know `serverless-pre-function` is a name
ctier emits.** A list that goes stale the moment someone adds a
component. The merge then skipped copying any estate plugin whose
name already sat on the fragment route. The catch-all went away. The
rewrite Lua went with it.

## Part 1–2 — derived collisions, replacement refuses

`replacement_findings(target, existing, produced)` walks **this**
`generate()` output against the existing files. No reserved-name
constant. A function-list plugin on both sides is concatenated, not
replaced. **Ctier's strip runs first**, then the estate functions,
then the strip again. Strip-first is C11 in that slot: a plugin that
breaks because a strip ran ahead of it was reading reserved headers.
The trailing strip is the same property for writers — APISIX has one
name per route, so an estate setter of `x-ctier-*` would otherwise
reach the backend. Any other same-slot different config refuses.
No override flag. The exception carries only the conflict report.

**C11 without replacement.** A later writer of a 1.5.0 header still
**refuses** (`breaks_c11`, rule `c11`) — `test_c11_without_replace_still_refuses_a_later_writer`.
A before-strip *reader* that does not replace anything still **warns
and proceeds**. That is named on the report as `warnedAndProceeded`.
It is a standing choice because requirement 3 and the boundary suite
own that gap on targets merge cannot reorder (Kong cors / jwt /
transformer). It is not refuse-by-default, and it is not silence.

## Part 3 — native collision behaviour

| Target | Native | What fragment did | What it does now |
|---|---|---|---|
| APISIX | **Replace.** One plugin name per route. | Silent skip of the estate copy; catch-all deleted. | Combine `functions` (strip, estate, strip), or refuse. |
| Kong | **Append** at the global plugin list. Route-level, one name is typical; a second is undefined. Catch-all route plugins vanished with the route. | Global append. Catch-all plugins dropped. | Copy catch-all plugins onto ctier routes; refuse a name that already sits on the route with a different config; refuse a second global `ctier` with a different config. |
| Apigee | **Error** at deploy on duplicate policy names. | Second loop **overwrote** `apiproxy/policies/*` of the same path. | Refuse if the path exists with different content. Never overwrite. |

## Part 4 — re-runs against the intact fixture

Estate rewrite Lua now sits on `getBalance` (asserted by reading the
merged YAML). Function order is strip, estate, strip.

APISIX fragment precedence **passed**. Kong fragment still **failed**.
`X-Estate-Seen` reaches echo; `x-ctier-forged` does not (trailing
strip). The 16 differential on APISIX fragment still agrees (level-2
and level-3).

The first live pass of APISIX precedence failed because the estate
Lua wrote `x-ctier-forged` and then scanned headers, so the probe
recorded its own write. Scan-then-write is the fixture now.

## NEW-MATTER

Concatenating `functions` is still a merge, not “rename yours.”
Strip-first is the C11 order; a second implementation that refuses
the slot instead of concatenating would also be defensible.
Whether requirement 3 can be dropped for APISIX fragment in the spec
README follows this holding in live tests.
