# 19 — the boundary conformance suite

`boundary-suite/0.1.0-draft` lives in the engine. It is not in the
specification. A format used by one implementation is a
serialisation; a format used by two is an interface, and only the
second has been tested as one.

The classification corpus establishes that two implementations agree
on a decision. This one establishes that they behave the same at the
wire. Neither establishes that either is *correct* — both could agree
and both be wrong.

---

## Part 0.1 — is the join key on an ordinary `200`?

**No.** `202` relays `x-ctier-correlation-id` (and `X-Correlation-Id`)
to the client. Execute sets the join key on the **service request**.
The client's `200` from getBalance does not carry it.

Equality is therefore **reference-only**: a case declares
`requires: [recordSource]`, the runner matches the
backend-observed join key to `GET /v1/ledger?type=decision`. An
implementation without a record source skips those cases and reports
them skipped. The downstream `200` contract was not extended.

## Part 0.2 — can the task-16 fixtures host a probe?

| Target | Cheapest probe | Live? |

The 16 APISIX fixture's rewrite Lua at 30000 is **not** copied onto
merged ctier routes: merge skips a plugin name the fragment already
has. The competing setter 16 documented does not sit on getBalance.
A probe has to be injected; relying on the estate plugin of the same
name would have made fragment precedence vacuously pass.

Kong's estate `request-transformer` (801) does sit before ctier
(800). The injected `pre-function` is still the cheapest thing that
can *record* what it saw.

## The suite

Ten cases. `absent` / `present` / `equals` only. No tier, no
disposition, no custody internals.

`requires`: `observer`, `probe`, `recordSource`. Skips are counted
apart from passes.

Observer contract: `GET /_harness/requests`, JSON array of
`{method, path, headers}` with lowercase keys. The reference runner
also accepts the echo body's `headers` for the request it just sent
— the same snapshot as the last log entry.

## What lifting 14c and 16 made visible

Those tests were checking values without saying so.

- **`x-ctier-tier != "9"`**, not “the name is absent.” The gateway
  re-emits the name. This draft has no `notEquals`, and will not
  `equals` a compiled tier. `X-Ctier-Tier` is therefore not an
  `absent` case.
- **`idempotency-key != "agent-idempotency"`**, not name-absent.
  Level 3 writes the derived key under that name. Inbound is the
  equals-to-ledger case; `X-Idempotency-Key` stays a valid `absent`.
- **Echo JSON as the observer**, never `GET /_harness/requests`
  except the chokepoint tests. The contract now names the GET; the
  body is a documented convenience.
- **Status 200 assumed**, never asserted. This suite still does not
  assert a disposition.
- **16's `x-estate-seen == 1`**: the estate still ran. Not a header
  contract. Not duplicated here.
- **202 dual-emit** of the join key is downstream. Out of scope.

The probe does not watch `Idempotency-Key`. An after-strip Kong
`post-function` would always see the derived key and fail bundle
precedence for the wrong reason.

## The question this suite exists to answer eventually

The classification corpus cannot see the wire. This suite can. It
still cannot say the wire is *right* — only that two fixtures, or
two implementations, showed the same headers. Promoting the draft
is 12b's rule: when a second implementation has been held to it.

Until then it is a serialisation that would have failed 14a–14c
instead of passing through them.

## NEW-MATTER (for the spec repo; this file is not that list)

- A fourth assertion kind (`notEquals`) for forged values on names
  the enforcement point re-emits (`x-ctier-tier`,
  `x-ctier-deployment`, `Idempotency-Key`).
- Whether ordinary `200` should carry `x-ctier-correlation-id`. Not
  done here; that is `spec/headers.md`.
- The APISIX fragment merge drops an existing
  `serverless-pre-function` on name collision. Requirement 3 cannot
  be satisfied by “the estate already had a rewrite plugin” if that
  plugin is the same name as the strip.
