## Accidental pass

Would any gate check have passed llama3.2 **by accident**? Q1 did pass,
and it is the check most likely to look like a description of 15's
failure (narrated tool calls) while actually testing a weaker class
(one trivial GET). This 3.2B model **has** that class. Q2 and Q3, the
classes 15 actually missed (dependent second call; wire retry on 429),
are 0/5. Q4's fail is a measurement miss, not a context overflow: a
parser that had read `/api/ps` `context_length` would have admitted
this model on Q4 too. A gate that admitted llama3.2 on Q1 (and would
have on Q4) still refuses it on Q2 and Q3. Those two are the class
detectors. Q1 passing this subject is not a retune; it is what a
trivial GET measures.
