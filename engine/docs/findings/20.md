# 20 — boundary-suite/0.2.0-draft

Every change in this bump came from writing the format down, not from
a failure. 0.1.0's live matrix was green. 0.2.0's is green too. The
work was at the desk: a kind the old tests were using without naming,
a status they assumed, a field a result needed in order to be a
result. Running the suite did not find those. Declaring what a case
is allowed to say did.

That generalises. A green run is agreement with whatever the tests
happened to check. A format is a list of checks someone else can
disagree with. This project has now written the wire format down
late twice in a week (19, then this). Next time, write the kinds
before the first green run, not after the third.

---

## Assertion-kind changes

No 0.1.0 case was rewritten from `absent` to `notEquals`. The
wrong-kind checks lived in 14c and 16's live tests, not in the
suite. 0.1.0 had a hole rather than a lie.

| Case | 0.1.0 | 0.2.0 | What it was actually asserting |
|---|---|---|---|
| *(none — new)* `forged-tier-not-surviving` | missing. 19 refused `absent` for a re-emitted name and had no `notEquals`. | `notEquals: {x-ctier-tier: "9"}` on a declared `200` | the agent's `9` did not survive. Not that the name is gone. Not that the surviving value is the compiled tier. |
| `derived-idempotency-present` | `present: [idempotency-key]` | `present` **and** `notEquals: {idempotency-key: agent-idempotency}` | 0.1.0's `present` would have passed a surviving forge. Occupancy is not replacement. |
| the other nine | `absent` / `present` / `equals`, status assumed | same kinds, `status: 200` declared | kinds did not move. Status stopped being an assumption. |

`equals`-the-compiled-tier was not added. The classification corpus
already owns that claim. This suite's job at the wire is that the
agent's value is gone.

Unknown-namespace names and the aliases stay `absent`. Those names
are not re-emitted. `X-Idempotency-Key` stays `absent`;
`Idempotency-Key` does not.

## Vacuous status

A case whose request is refused where the author expected success
used to pass `absent` because nothing arrived. Declaring `status`
closes that: header assertions run only on a match.

**No migrated case was relying on it.** Every live row below
observed `200` against a declared `200`. The hole was real in the
format (the unit suite fails a 401 that would have passed `absent`)
and unused by these cases. That is still worth the line: a test that
goes green for the wrong reason is the shape this bump exists to
stop shipping.

## NEW-MATTER (for the spec repo; this file is not that list)

- `notEquals` as a fourth assertion kind, for forged values on names
  the enforcement point re-emits. 19 listed it; 0.2.0-draft now has
  it. Promote with the format, not as a fifth kind that asserts the
  compiled tier.
- Presence of a re-emitted name is not occupancy. `present` on
  `Idempotency-Key` would have passed the agent's value surviving.
  If the spec talks about "the header is present," it has to say
  whose value.
- Declared expected status on a wire case. Assumed `200` is how a
  refused request passes `absent`. Not a disposition.
- Still not done here, still `spec/headers.md`: whether ordinary
  `200` should carry `x-ctier-correlation-id`.
