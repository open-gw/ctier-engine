# 13b — delegation and token exchange

The last piece of ADR-003. An expanded delegation is supposed to be
refused at token exchange so the enforcement point never sees a valid
credential with broader scope than its parent. That is the **standard**
profile. **Constrained** puts the check back at the gateway.

Which of those this rig can deploy is a fact about Keycloak 26.3.3.

## Experiments

Same shape as 08c. Live, `pytest --live`, Keycloak 26.3.3 arm64, no
network at test time. Operation scopes were moved from default to
optional for the run: default scopes are always minted, and exchange
cannot drop them. That move is an Admin-API accommodation for the
experiment, not a `generate()` change — E2 failed, so generate was
not asked to emit it.

| Experiment | Hypothesis | Result |
|---|---|---|
| E1 | Standard token exchange is available; a `scope=` subset is a new token that omits the rest | **Holds**, once operation scopes are optional. `scope=operation-getBalance` produced a token whose `scope` was exactly that. With scopes left as 13a's defaults, exchange returned 200 and **every default scope** — reduction was requested, not performed. |
| E2 | An expanded request, including **re-exchange** of a reduced token asking for a dropped scope, is refused by importable configuration | **Falsified.** Re-exchange without an executor returned 200 and restored `operation-initiatePayment`. `downscope-assertion-grant-enforcer` is not a valid client-policy provider on 26.3.3 (`does not have valid provider, or has invalid configuration`). Keycloak documents that executor from 26.5; this pin does not have it. |
| E3 | A voluntarily reduced token is 200 on the held operation and 401 on the omitted one | **Holds** as detection. `GET /accounts/…/balance` 200; `POST /payments` 401. No new plugin. This is exclusion's shape: prevention at the AS, detection at Kong. Prevention is what E2 could not establish. |

E2 is the fork. It failed. The rest of a standard-profile generator would
have told us nothing useful. `feat(generate)` is omitted.

## What is deployable

**Constrained.** This Keycloak will downscope when the client asks
nicely (E1) and Kong will notice a missing scope (E3). It will also
give the scope back on the next exchange (E2). Asking nicely is not
enforcement. The standard profile assumes the AS refuses expansion.
This rig cannot make it refuse from configuration.

Constrained is already a named deployment profile (ADR-003, corpus
`profile`). A later task that takes that path may put a chain check
at the enforcement point. This task does not.

Upgrading the pin to a Keycloak that ships the executor is a different
decision. It is not this experiment, and it is not a licence to claim
the standard profile on 26.3.3.

## What the realm model would not express

- **Default scopes cannot be reduced.** 13a granted every classified
  operation as a default client scope so every token carried the full
  set. Exchange treats those as compulsory. Optional scopes plus a
  `scope=` parameter are what made E1's reduction real. That is a
  generate-time choice, not taken here because E2 failed.
- **`downscope-assertion-grant-enforcer` is not a provider on 26.3.3.**
  The attribute `standard.token.exchange.enabled=true` is importable
  and was enough for E1. The executor that would have made E2 hold is
  not. Same class of finding as 13a's `cid` mapper: the product and
  the artefact we can import are not the same surface.
- Re-exchange is the hole the grant leaves open. A reduced token plus
  `scope=` of a dropped name is a new token that carries it.

13a's `cid`, admin-cli, `operation-foo`, dummy jwt `secret`, and
`serviceAccountsEnabled` still apply. They are not restated.

## Generate

Not changed. Emitting an exchange switch and optional scopes without
an enforcer would document a courtesy, not a profile.

## NEW-MATTER

None. ADR-003 already named the two profiles. That this Keycloak
implements the grant and not the enforcement is a measurement of a
product, not a mechanism.

The 30-second token lifetime remains in [`measurements.md`](../measurements.md).
This task adds no figure there.
