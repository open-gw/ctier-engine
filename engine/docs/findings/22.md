# 22 — the derived idempotency key at Level 2

Date: 16 September 2026. Requires 20. Independent of 21. Did not
edit the spec. Did not add a Lua HMAC to any target.

## Part 0 — what the key derives from

`derive_idempotency_key` (engine/ctier/classifier.py) HMAC-SHA256s
six fields joined with `U+001F`, then hex-encodes the digest. The
fields, in order:

1. `op.anchor()` — declared `operationId`, or `METHOD path_template`
   if none
2. `req.path`
3. `json.dumps(dict(sorted(req.query.items())), separators=(",", ":"))`
   — Python's default `ensure_ascii=True`
4. the body, as below
5. `req.agent_id`
6. `req.task_id or ""`

The HMAC key is `GovernanceConfig.hmac_key` (default
`ctier-dev-key-replace-in-production`). Method is not a field of
its own. Headers other than the agent/task identity used above are
not in the material.

**The body is in the hash.** If `req.body` is truthy, the function
`json.loads` then `json.dumps(..., sort_keys=True, separators=(",", ":"))`.
On `ValueError` or `TypeError` it uses the **raw body string**.
Absent and empty body both become `""`.

That is the stop the task named. Agreeing on a canonical form for
arbitrary bodies, across two languages, at request time, is a
different problem from agreeing on an operation anchor and a
selected set of parameters. The rest of this finding still names
the 500 and records the differential that already exists in-tree.
It is not a basis for implementing a Level-2 Lua key.

## Part 1 — why 14c 500'd

The call was:

```
ngx.hmac_sha256("ctier-dev-key-replace-in-production", material)
require("resty.string").to_hex(key)
```

**Cause: `ngx.hmac_sha256` is not an OpenResty API.** The field is
nil. Calling it is `attempt to call field 'hmac_sha256' (a nil
value)`, which Kong surfaces as 500 on every Level-2 execute.

This is not a wrong-argument bug on a working primitive, and it is
not a later failure in the Level-2 path. 14c already showed the
rest of that path is fine: `ngx.md5` of a minted string succeeded
on the same execute, then was dropped because it is not C7.

OpenResty ships `ngx.hmac_sha1` and `ngx.md5`. HMAC-SHA256 needs
`resty.openssl`, `lua-resty-hmac`, or an equivalent that this
plugin sandbox was not using. `resty.string.to_hex` is ordinary
OpenResty; the process never reached it.

Awkward, not impossible. The 500 does not decide the specification
question. Agreement does.

## Part 2 — the differential

No Lua was added. The comparison is Python
`derive_idempotency_key` against (a) a Python reconstruction of the
abandoned 14c Lua join (sorted query, **raw** body, string-concatenated
query object) and (b) the Apigee JS that is still generated:
`[anchor, path, '{}', '', agent, task].join('\u001f')`.

| Edge | Python vs abandoned Lua | Python vs Apigee JS |
|---|---|---|
| Empty query, empty body (happy path) | **agree** | **agree** |
| Query key order | agree (both sort) | **diverge** (JS ignores query) |
| Absent vs empty query value | agree with each other; both distinguish the two | **collide** (JS ignores query) |
| Query value that needs JSON escaping (`"`) | **diverge** | diverge |
| Unicode in query (BMP) | **diverge** (`\\u00e9` vs UTF-8) | diverge |
| JSON body key order | **diverge** (Python canonicalises; Lua hashes the bytes) | diverge (JS ignores body) |
| JSON whitespace | **diverge** | diverge |
| Non-JSON body | agree (both raw) | **diverge** |
| Unicode in JSON body, BMP and outside the BMP | **diverge** | diverge |
| Long compact JSON | agree when the bytes already match Python's dump | **diverge** |
| Absent vs empty body | agree | agree (both empty) |

The dangerous shape is present: **the happy path agrees, the edges
do not.** A single empty-body GET would have certified a Lua
fallback that then emitted a different key the moment the operation
had a body, a quoted query value, or a non-ASCII character.

Apigee's generated JS already does that against custody: it agrees
on empty GET and then **collides every body and every query** onto
that same key. A backend honouring `Idempotency-Key` across an
Apigee Level-2 hop and a Level-3 custody hop would see two keys for
one operation with a body, and one key for every distinct body of
the same operation.

Custody itself uses `derive_idempotency_key`, so Level 3 is the
Python function. There is no second language in the path that
custody uses.

## Part 3 — exclusion (draft, not a spec edit)

Level 2 enforces Tiers 1, 2 and 4 with no ctier runtime component.
It does not provide the derived idempotency key, so duplicate
execution under ordinary agent retry is not defended against at
this level.

## Recommendation

**Scope 1.5.0's MUST to deployments with a policy service.** Do not
implement a gateway-local HMAC. The primitive gap is fillable; the
canonical-form gap is not something this task should close, and the
in-tree Apigee JS already disagrees with Python on every request
that has a body or a query. Shipping a "fixed" Lua key would be
worse than no key: a migration from Level 2 to Level 3 would look
like a stronger defence while silently splitting the key space.

NEW-MATTER for the author: whether 1.5.0's derived-key MUST is
scoped to custody, and whether Apigee's request-time HMAC (empty
query, empty body) should be removed so Level 2 is uniform — strip
the agent's key, emit nothing.

## Architecture

The derived key is a function of request content, so it cannot be
resolved at deploy time. The compiled architecture exists to avoid
request-time computation. C7 is therefore the one criterion whose
mechanism is in tension with the project's central design choice,
rather than supported by it.

The tension is not resolved by a small amount of gateway-local
HMAC. HMAC is the cheap part. The expensive part is a canonical
form for the body that two languages, and three targets, would have
to compute identically on the request path — the kind of
recomputation portability.md exists to forbid, because every
recomputation is a place two targets can silently disagree. The
differential above is that disagreement, already, without a new
Lua. The adoption ladder therefore has a rung where one criterion
genuinely does not apply. Saying so is better than a MUST nobody
meets.
