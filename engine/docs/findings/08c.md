# 08c — the live differential run

## How the live suite is invoked

The default suite is unchanged: `pytest -q` from `engine/` with sockets
blocked and no containers. Live tests are marked `live` and skipped unless
`--live` is passed.

```
cd engine && PYTHONPATH=. pytest --live
```

That run needs docker. The skip reason on the default suite does not mention
docker; it says to invoke with `pytest --live`. The mock echo is in
`targets/kong/live/echo.py`. Kong is DB-less, `KONG_DECLARATIVE_CONFIG` at
startup, `KONG_PLUGINS=bundled,ctier`. No decK, no admin API. The proxy image
is the plugin as it would be deployed — no debug variant.

## Experiments

Each is a named test in `tests/live/test_kong_assumptions.py`. Recorded in
`targets/kong/ASSUMPTIONS.md`.

| Experiment | Assumption | Result |
|---|---|---|
| E1 | Route per operation resolves the operation | Holds. `GET /accounts/12345/balance` echoed tier 1, operation `getBalance`. |
| E2 | Kong resolves path specificity itself | Holds with the generator's `regex_priority` hint. Literal `/orders/summary` echoed tier 1; templated `/orders/abc` returned 423. 06's pair differs by method, so the experiment used GET on both. Equal-priority unaided preference was not tested. |
| E3 | Fail-closed arises from plugin precedence | Holds. `exportStatements` has no route-level `ctier`. The request returned 423. Absence of an override produced Tier 4. Part 3 was run. |

E3 is the compile-time binding argument on a second gateway. It survived this
translation. That is evidence the argument generalises this far, not evidence
it generalises to every platform.

## Differential summary

24 cases against `ReferenceAdapter` and `KongAdapter`. **18 agree, 6
disagree.** Overall `agree: false`. C11 agrees.

The six disagreements are the same shape: classifier `withhold` (tier 3)
versus Kong `refuse-provisioning` (403, projected as tier 4). Kong is a
Level 2 target without custody; task 06 maps Tier 3 to the provisioning
refusal. 08a already placed agreement on that row out of scope until custody
exists. Kong is not wrong relative to the artefact it was given. The
classifier expect is not wrong relative to the model. They measure different
things.

| id | Classifier | Kong | Why |
|---|---|---|---|
| `generated-updateCommunicationPreferences` | 3 withhold | 4 refuse-provisioning | T3 without custody |
| `generated-updateCustomerProfile` | 3 withhold | 4 refuse-provisioning | T3 without custody |
| `generated-modifyCreditLimit` | 3 withhold | 4 refuse-provisioning | T3 without custody |
| `bounds-exceeds-listTransactions` | 3 withhold | 4 refuse-provisioning | bounds raised to 3 |
| `bounds-decimal-listTransactions` | 3 withhold | 4 refuse-provisioning | bounds raised to 3 (`101.0`) |
| `bounds-scientific-listTransactions` | 3 withhold | 4 refuse-provisioning | bounds raised to 3 (`1.01e2`) |

No disagreement on execute-tier rows, including `listTransactions` in-bounds
and `raiseDispute` at compiled 4. No disagreement on undeclared (C2),
exclusion, or C11.

**C11.** `PUT /config/feature-flags` with `x-ctier-tier: 1` returned 423.
`backendReached: false` — the echo was not called, so a client-supplied
header could not have reached the backend. The case is no longer a
placeholder. A pass here is the first genuine test of the attack that
collapses the model.

## What remains unproven

This is Kong, one version (3.9.3), DB-less, this plugin, this generator, this
corpus. It is not a portability proof.

**Apigee was not in this run.** There is no local Apigee runtime. Its bundle
is golden-file correct and differentially unproven. A green Kong run does not
verify the Apigee target.

**Accumulation** is not in the corpus. Stateless cases cannot hold a session
floor.

**Custody** is not implemented. The six T3 rows are the evidence of that, not
a Kong defect.

**Delegation-chain integrity** is excluded in the standard profile.

**E2 unaided.** Literal preference at equal `regex_priority` was not tested.
The generator still sets the hint.

No NEW-MATTER. The mock echo is harness infrastructure. Plugin precedence
producing fail-closed is the compile-time binding argument observed, not a
new mechanism.
