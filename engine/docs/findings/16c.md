# 16c — is APISIX's conformance general, or same-slot only?

16b restored a structural guarantee inside a shared proxy by bracketing
the estate. That was the first time the compiled-absence family survived
coexistence, and 16a had recorded it as an open question. These two
experiments ask whether bracketing is a **general technique** or an
**accident of plugin models**.

It is accidental.

## E1 — falsified

Hypothesis: APISIX fragment mode is C11-conformant against any estate.

Second fixture: `existing/apisix-outside-slot.yaml`. The header reader
is **`serverless-post-function`** on a **`global_rules`** entry, rewrite
phase, `_meta.priority` **30000** (above strip 21000). It is not
`serverless-pre-function`. Merge cannot concatenate it into the strip
slot. The probe is task 19's: it records reserved inbound names as
`x-boundary-probe`.

Live: `strip-precedence` **failed**. The probe observed a client-injected
reserved header. Bracketing does not extend past the shared plugin name.

Same-slot estates (16 fixture) still pass. That is a real, bounded
result. Requirement 3 continues to apply to APISIX **in general**.

## E2 — held, bounded

ctier's Kong `PRIORITY` is a constant the plugin declares. Raised from
800 to **10000** — above cors (2000), jwt (1005), request-transformer
(801). A harness probe at **1500** (`ctier-estate-probe`) then runs
*after* the strip: precedence **passed** against `existing/kong.yaml`.

`pre-function` is **1000000**. The same estate with an injected
pre-function probe: precedence **failed**. No number we compile is
above that, and the estate is not known when the plugin is built.
Raising priority is a **reinstall**, not a redeploy.

The 16 fixture's `x-ctier-forged` setter was removed from Kong's
request-transformer. At 10000 that plugin runs after the strip; leaving
the setter would have made it a later writer of a 1.5.0 header, which
inspect already refuses. X-Estate-Seen remains.

Bound: **conformant against Kong readers below priority 10000**.

## Part 3 — the result names the estate

`boundary-report/0.1.0-draft` gained `estate`. Not a case-format change.
A precedence pass on APISIX fragment against `existing/apisix.yaml` and
a fail against `existing/apisix-outside-slot.yaml` can coexist.

## Recommendation (not applied)

Requirement 3 stays universal for fragment mode, with two bounds named:
APISIX only where a reader shares ctier's `serverless-pre-function`
slot; Kong only against readers below priority 10000. The evidence
table in `spec/conformance.md` should grow an estate column.
