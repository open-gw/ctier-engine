# 06c — compile the decision, not the declaration

## How the compile-the-declaration bug was found

06a's findings recorded that Apigee compiled a resolved floor on bounded
operations while Kong compiled `x-ctier-tier`. That was treated as a Kong
starting-tier miss against the classifier. Reading it again, the miss was
not Kong-specific and not bounds-specific: the generator was compiling an
*input* where it should compile a *decision*. `Classifier.classify` stage 2
takes `max(declared, computed)`. `_resolved_tier` returned the declared
field whenever it was present.

The 06a special case (bounded operations compile stage 2; unbounded compile
the declaration) made Apigee internally inconsistent and hid the same bug
on every unbounded operation where computed exceeds declared.
`raiseDispute` is that case in the reference document: declared 3, criteria
compute 4. The corpus already expected 4. The Apigee golden compiled 3.

No differential harness existed to catch this. 08c is built to test three
Kong routing hypotheses, not to ask whether the generator copied the wrong
field. The bug was found by reading a report. That is worth recording
before 08c runs, so a red run there is not asked to explain a generator
defect it was not designed to see.

## What changed when the oracle changed

Spec 1.1.6 defines the bound comparison as decimal-numeric. The classifier
used `int()`, which is the fail-open reading the spec now names: `101.0`
does not escalate. The oracle now parses a decimal (`Decimal`).

No existing golden or corpus `expect` changed as a result. Every bound case
already in the corpus used an integer string (`101`, or no parameter). The
fail-open was latent, not encoded. The six spec 1.1.6 cases are new
handwritten extras; they are additions, not rewritten expects.

Part 1 golden changes were generator corrections, not oracle changes:
`AM-Tier-raiseDispute` 3→4, Kong `listTransactions` config 1→2 (then bounds
raises to 3, matching the classifier).

## Did any target need adjustment?

Apigee's nested `request.queryparam.<parameter> > <max>` is already a
numeric comparison. It matches 1.1.6 without a generator change.

Kong's plugin uses `tonumber(raw, 10)`. LuaJIT follows Lua 5.1, where base
10 still accepts a decimal part and an exponent, so `101.0` and `1.01e2`
should escalate. The plugin was not changed. There is no Lua interpreter in
the toolchain; that reading is from the language manual, not an execution.
Lua 5.2+ `tonumber` with an explicit base is integer-only — if Kong were
ever run on that, it would fail open. 08c is the first live check.

No NEW-MATTER. Compiling `max(declared, computed)` is the classifier's
stage 2, emitted rather than recomputed.
