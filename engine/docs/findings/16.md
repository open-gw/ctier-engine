# 16 — fragment mode

Bundle mode emits a complete proxy. Fragment mode emits policy that
merges into an existing one. The existing proxy is the adoption
story; the bundle is the demo.

## Part 0 — the fixture

A cluttered proxy per target lives in `tests/fixtures/existing/`:
rate limiting, CORS, request logging, an authentication story (jwt
is added by the fragment, as it is in bundle), and a component that
reads or rewrites headers.

- **Kong:** global `cors` and `request-transformer` (adds
  `X-Estate-Seen` and `x-ctier-forged`), route-level `rate-limiting`
  and `file-log`.
- **APISIX:** catch-all with `limit-count`, `cors`, `http-logger`,
  and rewrite-phase Lua that sets the same two headers.
- **Apigee:** SpikeArrest, CORS AssignMessage, MessageLogging that
  interpolates `x-ctier-tier` / `x-correlation-id`, and JS that
  *reads* `request.header.x-ctier-tier`.

## Part 1 — strip precedence

| Target | Declarative pin? | Against arbitrary existing config? |
|---|---|---|
| Kong | No. Plugin PRIORITY is a constant on the plugin (800), not a deck field. | **Not C11-conformant.** CORS 2000, jwt 1005, request-transformer 801 all run *before* ctier. |
| APISIX | Only among plugins we emit (`_meta.priority` 21000 on strip). | **Not C11-conformant.** Existing rewrite-phase Lua can sit above that. The fixture's setter is 30000 and runs first; strip still follows it on merged routes. |
| Apigee | We prepend strip steps to ProxyEndpoint PreFlow. | **Not C11-conformant.** A PreProxy FlowHook is not in the artefact and runs first. |

No runtime check was added. The words are in
`docs/portability.md` requirement 3: fragment mode is not
C11-conformant. The operator must pin the strip first, and must not
let a later component write a 1.5.0 header.

The live competing setter is the fixture's `x-ctier-forged`. It runs
*ahead* of ctier on Kong (801 > 800) and *ahead* of APISIX strip
(30000 > 21000). Strip still removes it before the backend. That is
the setter case, not the reader case. CORS and jwt still *read*
agent headers before the strip. That is the C11 miss.

## Part 2 — the conflict report

`ctier-conflict-report.yaml` is emitted with every fragment.
Name collisions and writers that run *after* the strip refuse
(`GenerateError` rule `c11`, report attached). Everything else
warns.

**What the fixture caught that was not the point of the header
rewriter:** Kong and APISIX **CORS allow-lists name
`X-Correlation-Id`**. That is not a request read. The scanner
flagged it as a 1.5.0 name running before the strip (CORS priority
2000). Apigee's CORS AssignMessage does the same on
`Access-Control-Allow-Headers`. File-log / MessageLogging were the
expected readers. CORS was the surprise.

## Part 3 — tests

Offline, parameterised over three targets: merge keeps estate
plugins; strip steps prepend on Apigee; a `ctier` name collision
refuses; a Kong `post-function` writer at priority −1000 refuses.

Live, fragments applied over the fixture: differential corpus
level-2 and level-3 **agrees with the reference adapter** on Kong
and APISIX — the same classifications and dispositions as bundle.
`x-ctier-forged` from the estate setter does not reach echo.
Join key equals the decision record at level-3. Apigee has no local
runtime; claimed as artefact merge only.

## Part 4 — corpus dimension

Bundle and fragment produce the same decisions. The corpus should
not care how the configuration arrived. **No dimension is needed.**
14c's pending proposal for observed upstream headers is a different
question and was not folded in.

## What fragment cannot reproduce, because it was never about design

Bundle's guarantees that fragment does not have:

1. **Strip before any reader.** Bundle has no other reader. Fragment
   shares the path with CORS, jwt, logging, and whoever else was
   already there.
2. **No later writer of provenance.** Bundle's only writer of
   `x-ctier-*` is ctier itself. Fragment cannot stop a
   `post-function` at −1000; it can only refuse to emit when it
   sees one.
3. **Known order.** Bundle's order is the plugin we shipped.
   Fragment's order is the estate's, plus whatever we can pin.
4. **A catch-all that is ours.** The fixture's `/*` would have
   served unknown paths as 200. Merge drops it so undeclared stays
   423. That is us deleting the operator's route, not a guarantee
   we kept.

Those were properties of **ctier being alone**, not of the compiled
decision. Day one, without rebuilding the estate, the adopter gets
the same classifications and dispositions, a conflict report, and a
strip that runs when our plugin runs — not a path that nothing else
can see.

## NEW-MATTER

Requirement 3 (fragment strip precedence) belongs on the
specification's "what ctier requires of the deployment" list next
to the two 1.5.0 already states. This repository documented it in
`portability.md`; the spec README has not grown a third bullet.
