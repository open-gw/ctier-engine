# 31 — empty the deprecation table

Date: 17 September 2026. Independent of 27 and of M6. Did not edit the spec.

## Part 0

The task's four-row table was incomplete by one.

Derived from the code (ingress aliases, dual-emission, fallback
branches), compared with the task table:

| Path | In the task table? |
|---|---|
| `ledger-*` schema heads | yes (dated engine 0.2.0, still in scope) |
| ingress `composition` / `compositionDigest` | yes |
| dual-emitted `x-ctier-composition` | yes |
| downstream `X-Correlation-Id` on 202 | yes |
| Kong plugin config `composition` | **no** — already in `portability.md`, removal 0.3.0 |

Not shims: compose-time `compositionDigest`, corpus `composition`,
inbound strip of the withdrawn names, estate/boundary scanners, the
SQLite pending-column rename (`digest` + `digest_schema`). Those last
are not names the engine accepts on the wire.

## Part 1

All five removed. Old schema heads and digest fields raise. Persist
rejects the old keys. Plugin schema has no `composition` field.
Nothing emits `x-ctier-composition` or 202 `X-Correlation-Id` on
Kong, APISIX, or Apigee; `test_nothing_emits_withdrawn_names` is
13h's naming guard extended, with an explicit exception list of
strips and scanners.

## Part 2

Engine version is **0.3.0**. The deprecation table in
`docs/portability.md` is empty. Engine 0.2.0 was never published;
`ledger-*` left with the rest.

## Part 3

The live suite started and finished green **without** resetting the
rig's custody store. Historical pending rows, if any, were already
on the `digest` / `digest_schema` shape from 13h; they did not
depend on the ingress shims.

## Observation

Four shims accumulated in eleven days, each one correct in isolation and each one
carrying a version number nobody had reached yet. The table 13h introduced is
what made them collectively visible; without it they would have been four
unrelated kindnesses in four different files, and the first person to notice
would have been whoever tried to remove one.
